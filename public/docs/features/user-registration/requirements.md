ユーザー登録 要件定義書
=================

最終更新: 2025-08-30

1. 目的/概要
-----------
- 新規ユーザーがメールアドレスとパスワードでアカウントを作成し、初回ログイン可能な状態にする。
- 将来のメール検証や紹介コード、無料トライアル付与にも拡張可能な設計とする。

2. スコープ
---------
- 画面: `/register`（`src/pages/Register.tsx`）
- バックエンドAPI: `POST /api/auth/register`
- 成功時の遷移: トークン同梱時は自動ログイン→`/`、トークン無い場合は `/login` に誘導

3. 利用者/アクセス制御
------------------
- 未認証ユーザーのみアクセス。認証済みは `/` に誘導（将来拡張）。
- 完成までサイドバーからは非表示（機能一覧からのみ管理者が確認可能）。

4. 入力項目/バリデーション
----------------------
- 必須: `name` 最低2文字、`email` RFC準拠、`password` 8文字以上、`confirmPassword` 一致、`acceptTerms` チェック
- 任意: `referralCode`（英数/`_`/`-` 3-32 桁）

5. 非機能要件
------------
- セキュリティ: HTTPS前提、パスワードは平文保存禁止、ログ/エラーに出さない
- アクセシビリティ: ラベル関連付け、エラー `aria-live`、キーボード操作
- パフォーマンス: 入力応答 < 100ms、送信応答 < 3s（95パーセンタイル）

6. 成功/失敗シナリオ
-----------------
- 成功: 201で作成、ユーザー情報+（実装によっては）`token` 返却
- 失敗:
  - 400 入力不備
  - 409 既存メール
  - 503 DB接続不可
  - 500 予期しないエラー

7. API I/F（概略）
----------------
- POST `/api/auth/register`
  - req: `{ displayName, email, password, acceptTerms, referralCode? }`
  - res（現状）: `{ token?: string, user: { id, email, displayName, role, isVerified }, subscription? }`

8. 受入条件
---------
- 上記必須入力・バリデーションで作成可能
- 重複メールで 409 を返す
- UIでエラー表示が行われる（フォーム上とアラート）

9. 完了条件（要件）
----------------
- 要件が網羅され、レビューで承認済み（管理者チェックリスト全項目に合格）

10. 依存関係 / データフロー（明記）
-----------------------------
- フロントエンド:
  - 画面: `src/pages/Register.tsx`
  - API呼出: `src/services/api/authApi.ts` の `register(userData)`
  - トークン管理: `src/services/auth/TokenManager.ts` の `tokenManager.setTokens()` を利用（トークン同梱時）
  - 遷移: トークン同梱時 `/`、非同梱時 `/login`（メッセージ付き）
- バックエンド:
  - エンドポイント: `POST /api/auth/register`
  - バリデーション/重複チェック/パスワードハッシュ/ユーザー作成/（将来）メール検証トークン発行
- データフロー（概略）:
  1) ユーザー入力 → 2) クライアント側バリデーション → 3) API送信
  → 4) 成功レスポンス（token有無） → 5) token有: TokenManagerへ保存して即ログイン/ホーム遷移
  → 6) token無: ログイン画面へ誘導（状態メッセージ表示）

11. リスクと対応
---------------
- 重複メール大量試行（アカウント枚挙）: 409返却、エラーメッセージは一般化。レート制限/遅延応答を適用。
- 弱いパスワード/総当たり: クライアント/サーバ双方で強度要件、試行回数制限、IPベースレート制限。
- 通信経路保護: HTTPS必須、HSTS推奨。
- 機密情報露出: パスワード/トークンをログ/エラーに出力しない。PII最小化。
- CSRF/XSS: 登録はJSON API＋SameSite Cookie運用（必要時）。入力はエスケープ/サニタイズを徹底。
- 依存サービス障害（DB/メール）: 503ハンドリング、再試行誘導、アラート通知。
- 国際化/アクセシビリティ: ラベル/aria-liveの維持、将来多言語メッセージ対応。

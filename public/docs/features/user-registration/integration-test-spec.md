ユーザー登録 結合試験仕様書
=================

最終更新: 2025-09-01

1. 目的
-------
フロントエンド（/register）とバックエンド（/api/auth/register）間の結合を検証し、入力→API→トークン保存→遷移→表示/通知まで、要件・詳細設計に沿って一連のフローが成立することを確認する。

2. 対象
-------
- 画面: `src/pages/Register.tsx`
- API: `api/auth/register.ts`（Vercel Functions）
- 連携: `src/services/auth/TokenManager.ts`、`react-hot-toast`、`useAnalytics`

3. 前提/環境
------------
- 本番相当: Vercel 環境で `MONGODB_URI`, `JWT_SECRET`, `VITE_ADMIN_EMAILS` を設定済み
- CORS 設定: `https://work-time-tracker-five.vercel.app` およびプレビュー（`work-time-tracker-five-*.vercel.app`）
- 初期状態: 未ログイン、DBに重複しないテストメールを用意

4. シナリオ
----------
S1: 初期表示/UI
- /register を開く
- 必須フィールド・規約チェック・送信ボタンが表示される
- 未入力かつ規約未同意のとき送信ボタンが disabled

S2: バリデーション
- 名前/メール/パスワード/確認の同期バリデーションが発火し、エラーメッセージとアイコン表示が期待どおり
- パスワード強度表示が入力に応じて更新

S3: 正常登録（token同梱あり）
- 有効な値で送信
- 期待: HTTP 201、レスポンスに `token`/`user`
- TokenManager.setTokens が呼ばれ、`navigate('/')` へ遷移
- 成功トーストおよび analytics `register_success` が記録

S4: 正常登録（token同梱なし）
- サーバー設定により token を返さないケース
- 期待: `/login` に `state.message/state.email` 付き遷移

S5: 重複メール（409）
- 既存メールで送信
- 期待: email フィールドにエラー、トーストは出ない、画面は維持

S6: 入力不備（400）
- 不正パスワード等で送信
- 期待: 上部アラート + トースト、フォーム値は保持

S7: サービス不可（503）
- DB停止等の障害（意図的に再現可）
- 期待: 上部アラート + トースト（再試行ガイド）

S8: ネットワーク障害
- 通信遮断/タイムアウトを注入
- 期待: 汎用エラートースト、UIはクラッシュしない

S9: 紹介コード連携
- `/register?ref=abc123` で表示
- 期待: フィールドに `abc123` が自動入力、成功時に `clearReferralCode()` が呼ばれる

S10: アクセシビリティ
- ラベル/`htmlFor` と `id` の対応、`aria-live` によるエラー告知、キーボード操作のみで登録可能

S11: セキュリティ/ログ
- 送信時にパスワードがログ/計測に出力されないこと
- 例外時も平文パスワードが console に出ないこと

5. 非機能/性能
--------------
- 初回表示 p95 < 1.5s（本番相当）
- 登録実行→応答 p95 < 3s（本番相当）

6. データ/後片付け
-----------------
- 作成したテストユーザーと初期サブスクリプション（free/trialing）を削除

7. 合否判定
------------
上記 S1〜S11 をすべて満たし、UIがクラッシュせず、期待どおりの遷移/表示/通知/記録が行われること。

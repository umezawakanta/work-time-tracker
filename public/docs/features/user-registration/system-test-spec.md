ユーザー登録 総合試験仕様書
=================

最終更新: 2025-09-01

1. 目的
-------
本番相当環境において、ユーザー登録機能（/register ←→ /api/auth/register）が要件定義・基本設計・詳細設計・結合試験仕様に沿って、安全・確実・快適に動作することを総合的に確認する。

2. 対象
-------
- 画面: `src/pages/Register.tsx`
- バックエンド（Vercel Functions）: `api/auth/register.ts`
- 連携: `TokenManager`, `react-hot-toast`, `useAnalytics`

3. 環境/前提
------------
- デプロイ先: Vercel（本番またはプレビュー）
- 環境変数: `MONGODB_URI`, `JWT_SECRET`, `VITE_ADMIN_EMAILS` 設定済み
- CORS: `https://work-time-tracker-five.vercel.app` と `work-time-tracker-five-*.vercel.app`
- DB: 接続確認済み（`/api/db/status` → `connected: true`）
- 初期状態: 未ログイン／検証メールは未使用のテストアドレスを用意

4. 試験観点（システム）
----------------------
S1. 認証制御
- 未ログインで `/register` にアクセスできること。ログイン済みは将来のリダイレクト仕様に影響しないこと。

S2. 初期表示/UI
- 入力（名前/メール/パス/確認/紹介コード）・規約チェック・送信ボタン表示。
- 規約未同意か未入力で送信ボタンが disabled。

S3. バリデーション/強度表示
- 入力に応じた同期バリデーションが正しく表示（フィールド直下/アイコン）。
- パスワード強度メーターが更新される。

S4. 正常登録（token 同梱あり）
- 有効値で送信→ HTTP 201、レスポンス `token`/`user` を受領。
- `TokenManager.setTokens` で保存→ `/` へ遷移。成功トースト表示、`register_success` 記録。

S5. 正常登録（token 同梱なし）
- サーバー設定で token 無返却ケース→ `/login` に `state.message/state.email` 付き遷移。

S6. 重複メール（409）
- 既存メールで送信→ email フィールドにエラー表示。トーストは出さない。フォーム値保持。

S7. 入力不備（400）
- 不正値送信→ 上部アラート + トースト。フォーム値保持。

S8. サービス不可（503）
- DB停止など障害時→ 上部アラート + トースト（再試行ガイド）。UIはクラッシュしない。

S9. ネットワーク障害
- 通信遮断/タイムアウト→ 汎用エラートースト、UIはクラッシュしない。

S10. 紹介コード連携
- `?ref=abc123` で表示→ フィールド自動入力。成功時 `clearReferralCode()` が呼ばれる。

S11. アクセシビリティ
- ラベルと `htmlFor/id` の対応、重要メッセージの `aria-live` 告知、キーボードのみで登録完了可能。

S12. セキュリティ/ログ
- パスワード/トークン等の機微情報をログ/計測へ出力しない。例外時も平文パスワードを出力しない。

5. 非機能（目標値/合否）
----------------------
- 初回表示（/register）: p95 < 1.5s
- 登録送信→応答: p95 < 3s
- エラー時のユーザビリティ: 次アクションを誘導（再試行/ログイン/問い合わせ等）。

6. データ/後片付け
-----------------
- 作成したテストユーザーと付随の初期サブスクリプション（free/trialing）を削除。

7. 監査/計測
------------
- Analytics: `register_view`, `register_success`, `register_error` を計測（PIIは含めない）。
- 監査ログ: 成功/失敗、reason、email（マスク可）、タイムスタンプ、クライアントIP（マスク可）。

8. 合否判定
-----------
S1〜S12 の全項目を満たし、UIがクラッシュせず、期待どおりの入力・API・保存・遷移・通知・計測が成立していること。

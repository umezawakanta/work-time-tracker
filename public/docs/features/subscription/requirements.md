サブスクリプション 要件定義書
=================

最終更新: 2025-08-31

1. 目的/概要
-----------
- 有料プランの申込/解約/更新を安全かつ分かりやすく提供し、請求情報を一元管理する。
- 将来のクーポン、無料トライアル、年額/月額切替、同時端末数制限に拡張可能な設計とする。

2. スコープ
---------
- 画面: `/subscription`（`src/pages/SubscriptionPage.tsx`）
- バックエンドAPI: `POST /api/subscription/*`（決済ゲートウェイ連携）
- 成功時の遷移: 申込完了後は /subscription に戻り最新状態を反映（トースト/バッジ表示）

3. 利用者/アクセス制御
------------------
- 認証ユーザーのみアクセス可能。管理者は全ユーザーの状態を参照（将来の管理画面）。
- 完了までサイドバーからは非表示（機能一覧からのみ管理者が確認可能）。

4. 機能要件
----------
- プラン一覧の表示（Free/Pro…）。
- 申込/解約/更新/再開の操作と状態反映（有効/期限/次回請求日）。
- 支払い方法の登録/更新（カード末尾4桁・ブランド表示）。
- 請求履歴/領収書ダウンロード（リンク）。
- 失敗時のリトライ/再認証フロー（SCA等）。

5. 非機能要件
------------
- セキュリティ: HTTPS必須、トークン/PIIをログに出さない、決済情報はゲートウェイにのみ保持。
- パフォーマンス: 主要アクション応答 < 3s（p95）、画面初期表示 < 1.5s（キャッシュ可）。
- 可用性: 決済ゲートウェイ障害時は読み取り専用で案内表示。
- アクセシビリティ: ラベル/説明、エラー `aria-live`、キーボード操作。

6. 成功/失敗シナリオ
-----------------
- 成功: 申込完了→有効化→次回請求/プランバッジ更新→トースト表示。
- 失敗: 400 入力不備、402 決済拒否、409 重複申込、503 ゲートウェイ不可、500 予期せぬエラー。

7. API I/F（概略）
----------------
- POST `/api/subscription/checkout`  req: { planId }  res: { sessionUrl }
- POST `/api/subscription/portal`    req: {}        res: { url }
- GET  `/api/subscription/status`    res: { plan, status, renewAt, card }
- POST `/api/subscription/cancel`    req: { atPeriodEnd?: boolean }

8. 受入条件
---------
- 認証ユーザーでプラン申込/解約/更新が行える。
- 状態/請求情報が画面に正しく反映され、エラー時に適切な案内を行う。
- 領収書リンクが表示される（履歴がある場合）。

9. 完了条件（要件）
----------------
- 本書の要件が網羅され、レビューで承認済み（管理者チェックリスト全項目合格）。

10. 依存関係 / データフロー
-------------------------
- 依存関係:
  - フロント: `src/pages/SubscriptionPage.tsx`、共有UI、トースト/バッジ。
  - バックエンド: `/api/subscription/*` 一連のエンドポイント。
  - 決済ゲートウェイ: Checkout/Customer Portal/Webhook。
  - ストレージ: サブスク状態（プラン/期限/次回請求/カード末尾4桁・ブランド）。
- データフロー（概略）:
  1) プラン選択→`POST /subscription/checkout`→`sessionUrl`取得
  2) 決済画面→成功→リダイレクト/ゲートウェイWebhook
  3) Webhookで購読状態を確定保存（冪等）
  4) 画面で`GET /subscription/status`→状態/請求情報を表示
  5) 解約/再開/支払方法更新は Portal/専用API→Webhook/ステータス反映

11. リスクと対応
---------------
- 決済拒否/SCA失敗: 明確な再試行導線・Portal誘導。402系エラー文言をユーザー向けに最適化。
- 二重申込/重複リクエスト: サーバー側で冪等キー処理・重複排除、UI側はボタン連打防止。
- Webhook遅延/失敗: リトライ/死信キュー、フロントはポーリング/手動更新で整合。
- ゲートウェイ障害: 読み取り専用モードで案内、後日再開のためのリマインダ提示。
- PII/カード情報露出: カード番号は保存しない（末尾4桁/ブランドのみ保持）。ログはマスキング。
- CSRF/XSS: JSON API＋SameSite、トークン/入力エスケープ。端末共有時の保護（Portalは再認証）。
- レート制限/DoS: 主要APIにレート制限、スロットリング/バックオフ。

12. プライバシー/データ保護
-------------------------
- 保存データ: plan/status/renewAt/card(last4, brand)のみ。完全なカード情報は保持しない。
- アクセス制御: 自ユーザーのみ閲覧/操作。管理系は監査ログ付与。
- 監査/ログ: 個人情報はマスクし、トレーサビリティ用のID/タイムスタンプのみ記録。

# 管理者ダッシュボード 要件定義書

最終更新: 2025-08-29

## 目的
運用・分析・設定を1箇所に統合し、管理者がサイト全体の安定運用と意思決定を高速化できるようにする。

## スコープ
- 概要: 主要KPIとシステム健康状態のダッシュボード
- ユーザー: 管理者のみ（RBAC: user.isAdmin or role === 'admin'）
- タブ構成:
  - 概要、ユーザー、優先アクション、分析、エラー監視、設定、診断集計、学習進捗

## 機能要件
1. メトリクス表示
   - ユーザー総数、アクティブ、MRR、稼働率、エラー率、未対応チケット
2. 分析
   - ページビュー推移、トップページ、リテンション簡易表
3. エラー監視
   - SSE心拍、自己診断、手動復旧、レポート一覧
4. 承認付き開発フロー
   - 自動判定(提案)/承認/有効の3指標を表示
   - 「次の段階を承認」ボタンで段階的に承認
5. アクセス制御
   - 非管理者はアクセス不可、未認証はログインへ

## 非機能要件
- パフォーマンス: 初期描画 < 2s（開発環境基準）
- 可用性: SSE切断時は自動復旧
- セキュリティ: 認証トークン付与、レートリミット、CORS対応済みAPIの利用
- アクセシビリティ: キーボード操作可能、色コントラスト遵守

## API/I/O
- 読み取り
  - GET /api/admin/metrics, /analytics/pageviews/daily, /admin/metrics/top-pages
  - GET /api/notifications/stream, /api/health, /api/db/status, /api/admin/error-reports
- 書き込み
  - POST /api/admin/actions/:id/complete（将来: 承認API）

## 完了条件
- 新フローに基づき system_testing → documenting → review → release_pending → complete
- 実APIでの動作が確認でき、モックが残っていないこと

## リスク
- 実データ未接続箇所の残存
- モックフラグとの整合性

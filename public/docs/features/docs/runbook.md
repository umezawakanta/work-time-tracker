# 📄 ドキュメント機能 運用手順書

## 1. 概要

### 1.1 目的
ドキュメント機能の運用・保守・監視に関する手順を定め、システムの安定稼働を確保する。

### 1.2 対象範囲
- ドキュメント機能の監視
- 障害対応
- パフォーマンス監視
- セキュリティ監視
- バックアップ・復旧
- 容量管理

## 2. 監視項目

### 2.1 システム監視

#### 2.1.1 可用性監視
- **監視項目**: ドキュメント機能の可用性
- **監視方法**: ヘルスチェックエンドポイント
- **監視頻度**: 1分間隔
- **閾値**: 可用性99%以上
- **アラート条件**: 5分間連続でダウン

```bash
# ヘルスチェックコマンド
curl -f https://work-time-tracker-five.vercel.app/api/health || echo "Health check failed"
```

#### 2.1.2 レスポンス時間監視
- **監視項目**: APIレスポンス時間
- **監視方法**: エンドポイント別レスポンス時間測定
- **監視頻度**: 1分間隔
- **閾値**: 
  - ドキュメント一覧取得: 3秒以内
  - ドキュメント内容取得: 2秒以内
  - 検索機能: 1秒以内

#### 2.1.3 エラー率監視
- **監視項目**: HTTPエラー率
- **監視方法**: ログ解析
- **監視頻度**: 5分間隔
- **閾値**: エラー率5%以下
- **アラート条件**: エラー率が10%を超えた場合

### 2.2 パフォーマンス監視

#### 2.2.1 メモリ使用量監視
- **監視項目**: サーバーメモリ使用量
- **監視方法**: システムメトリクス
- **監視頻度**: 1分間隔
- **閾値**: メモリ使用率80%以下
- **アラート条件**: メモリ使用率が90%を超えた場合

#### 2.2.2 CPU使用量監視
- **監視項目**: サーバーCPU使用量
- **監視方法**: システムメトリクス
- **監視頻度**: 1分間隔
- **閾値**: CPU使用率70%以下
- **アラート条件**: CPU使用率が85%を超えた場合

#### 2.2.3 ディスク使用量監視
- **監視項目**: ドキュメントファイルのディスク使用量
- **監視方法**: ファイルシステム監視
- **監視頻度**: 1時間間隔
- **閾値**: ディスク使用率80%以下
- **アラート条件**: ディスク使用率が90%を超えた場合

### 2.3 セキュリティ監視

#### 2.3.1 アクセスログ監視
- **監視項目**: 異常なアクセスパターン
- **監視方法**: ログ解析
- **監視頻度**: リアルタイム
- **検出条件**:
  - 同一IPからの大量アクセス
  - パストラバーサル攻撃の試行
  - SQLインジェクション攻撃の試行

#### 2.3.2 認証・認可監視
- **監視項目**: 認証失敗、権限エラー
- **監視方法**: ログ解析
- **監視頻度**: リアルタイム
- **アラート条件**: 認証失敗が10回/分を超えた場合

## 3. 障害対応手順

### 3.1 障害レベル定義

#### 3.1.1 レベル1（緊急）
- ドキュメント機能が完全にダウン
- セキュリティインシデント発生
- データ損失の可能性

#### 3.1.2 レベル2（高）
- 一部機能が利用できない
- パフォーマンスが大幅に低下
- エラー率が異常に高い

#### 3.1.3 レベル3（中）
- 軽微な機能不具合
- パフォーマンスの軽微な低下
- 警告レベルのアラート

### 3.2 障害対応フロー

#### 3.2.1 レベル1障害対応
1. **即座の対応**（5分以内）
   - アラートの確認
   - 影響範囲の特定
   - 緊急連絡の実施

2. **初期対応**（15分以内）
   - システム状態の確認
   - ログの収集・分析
   - 一時的な回避策の実施

3. **根本対応**（1時間以内）
   - 原因の特定
   - 修正の実施
   - 動作確認

4. **事後対応**（24時間以内）
   - 障害報告書の作成
   - 再発防止策の検討
   - 関係者への報告

#### 3.2.2 レベル2障害対応
1. **初期対応**（30分以内）
   - アラートの確認
   - 影響範囲の特定
   - ログの収集・分析

2. **対応実施**（2時間以内）
   - 原因の特定
   - 修正の実施
   - 動作確認

3. **事後対応**（48時間以内）
   - 障害報告書の作成
   - 改善策の検討

#### 3.2.3 レベル3障害対応
1. **対応実施**（4時間以内）
   - アラートの確認
   - 原因の特定
   - 修正の実施

2. **事後対応**（1週間以内）
   - 改善策の検討
   - 監視設定の見直し

### 3.3 具体的な障害対応手順

#### 3.3.1 ドキュメント機能ダウン時の対応
```bash
# 1. システム状態確認
curl -f https://work-time-tracker-five.vercel.app/api/health

# 2. ログ確認

# 3. データベース接続確認

# 4. 再起動（必要に応じて）
vercel deploy --prod
```

#### 3.3.2 パフォーマンス低下時の対応
```bash
# 1. リソース使用量確認
vercel logs --follow | grep -E "(memory|cpu|disk)"

# 2. スロークエリの確認
vercel logs --follow | grep -E "slow query"

# 3. キャッシュのクリア
# 必要に応じてキャッシュをクリア

# 4. スケーリング（必要に応じて）
# Vercelの設定でスケーリングを調整
```

#### 3.3.3 セキュリティインシデント時の対応
```bash
# 1. アクセスログの確認
vercel logs --follow | grep -E "(attack|injection|xss)"

# 2. 異常なアクセスのブロック
# IPアドレスベースでのブロック設定

# 3. セキュリティパッチの適用
# 必要に応じて依存関係の更新

# 4. 監査ログの保存
# インシデント関連のログを保存
```

## 4. バックアップ・復旧手順

### 4.1 バックアップ対象

#### 4.1.1 ドキュメントファイル
- **対象**: `public/docs/`ディレクトリ内の全ファイル
- **頻度**: 日次
- **保持期間**: 30日間
- **方法**: Gitリポジトリのバックアップ

#### 4.1.2 設定ファイル
- **対象**: 環境変数、設定ファイル
- **頻度**: 週次
- **保持期間**: 90日間
- **方法**: 設定管理システムでのバックアップ

#### 4.1.3 ログファイル
- **対象**: アプリケーションログ、アクセスログ
- **頻度**: 日次
- **保持期間**: 90日間
- **方法**: ログ管理システムでのバックアップ

### 4.2 復旧手順

#### 4.2.1 ドキュメントファイルの復旧
```bash
# 1. バックアップからの復旧
git checkout <backup-commit> -- public/docs/

# 2. ファイルの整合性確認
find public/docs/ -name "*.md" -exec md5sum {} \;

# 3. アプリケーションの再起動
vercel deploy --prod
```

#### 4.2.2 設定ファイルの復旧
```bash
# 1. 環境変数の復旧
vercel env pull .env.local

# 2. 設定の確認
vercel env ls

# 3. アプリケーションの再起動
vercel deploy --prod
```

## 5. 容量管理

### 5.1 ディスク容量監視

#### 5.1.1 ドキュメントファイル容量
- **監視対象**: `public/docs/`ディレクトリ
- **監視頻度**: 日次
- **閾値**: 1GB以下
- **対応**: 容量超過時の古いファイル削除

#### 5.1.2 ログファイル容量
- **監視対象**: ログファイル
- **監視頻度**: 日次
- **閾値**: 500MB以下
- **対応**: ログローテーション

### 5.2 容量最適化

#### 5.2.1 ドキュメントファイルの最適化
```bash
# 1. 重複ファイルの検出
find public/docs/ -name "*.md" -exec md5sum {} \; | sort | uniq -d -w 32

# 2. 不要ファイルの削除
find public/docs/ -name "*.tmp" -delete

# 3. ファイルサイズの確認
du -sh public/docs/*
```

#### 5.2.2 ログファイルの最適化
```bash
# 1. ログローテーション
logrotate /etc/logrotate.d/vercel

# 2. 古いログの削除
find /var/log -name "*.log" -mtime +30 -delete
```

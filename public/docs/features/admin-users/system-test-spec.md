# 管理ユーザー機能 システムテスト仕様書

## 概要
管理者がユーザー一覧を表示し、ユーザーの情報を更新・削除できる機能をテストします。

## テスト環境
- **本番環境**: https://work-time-tracker-five.vercel.app
- **テスト日時**: 2025-09-06
- **テスト担当者**: システムテスト担当者

## 前提条件
- 管理者権限を持つユーザーでログイン済みであること
- 管理ユーザー機能が`complete`ステータスであること
- テスト用のユーザーデータが存在すること

## テストケース

### TC-001: ユーザー一覧表示の基本動作
**目的**: ユーザー一覧が正しく表示されることを確認

**手順**:
1. 管理者としてログインする
2. `/admin/users`にアクセスする
3. ユーザー一覧が表示されることを確認する

**期待結果**:
- ユーザー一覧が表示される
- 各ユーザーの基本情報（名前、メール、ロール、ステータス）が表示される
- ページネーションが動作する
- 検索機能が利用できる

### TC-002: ユーザー検索機能
**目的**: ユーザー検索機能が正しく動作することを確認

**テストデータ**:
- 検索キーワード: メールアドレス、ユーザー名

**手順**:
1. 検索ボックスに検索キーワードを入力する
2. 検索結果が表示されることを確認する
3. 検索結果をクリアする

**期待結果**:
- 入力したキーワードに一致するユーザーのみが表示される
- 検索結果がリアルタイムで更新される
- 検索結果をクリアすると全ユーザーが表示される

### TC-003: ユーザー情報の更新
**目的**: ユーザーの情報を正しく更新できることを確認

**テストデータ**:
- 更新対象: ロール（user ↔ admin）
- 更新対象: アクティブ状態（有効 ↔ 無効）
- 更新対象: ブロック状態（ブロック ↔ アンブロック）

**手順**:
1. ユーザーのアクションメニューを開く
2. 更新したい項目を選択する
3. 確認ダイアログで「はい」をクリックする
4. 更新結果を確認する

**期待結果**:
- ユーザー情報が正しく更新される
- 更新後の情報が一覧に反映される
- 成功メッセージが表示される

### TC-004: ユーザーの削除
**目的**: ユーザーを正しく削除できることを確認

**テストデータ**:
- 削除対象: テスト用ユーザー

**手順**:
1. 削除対象ユーザーのアクションメニューを開く
2. 「削除」を選択する
3. 確認ダイアログで「はい」をクリックする
4. 削除結果を確認する

**期待結果**:
- ユーザーが削除される
- ユーザー一覧から削除されたユーザーが消える
- 成功メッセージが表示される

### TC-005: ページネーション
**目的**: ページネーションが正しく動作することを確認

**手順**:
1. ユーザー一覧のページネーションを確認する
2. 次のページに移動する
3. 前のページに戻る
4. 特定のページに移動する

**期待結果**:
- ページネーションが正しく表示される
- ページ移動が正常に動作する
- 現在のページが正しく表示される

### TC-006: ソート機能
**目的**: ユーザー一覧のソート機能が正しく動作することを確認

**テストデータ**:
- ソート項目: 作成日時、メールアドレス、名前

**手順**:
1. ソート項目を選択する
2. 昇順・降順を切り替える
3. ソート結果を確認する

**期待結果**:
- 選択した項目でソートされる
- 昇順・降順が正しく切り替わる
- ソート状態が保持される

### TC-007: レスポンシブ表示
**目的**: 画面サイズに応じてユーザー一覧が適切に表示されることを確認

**手順**:
1. デスクトップ画面（1024px以上）で表示を確認
2. タブレット画面（768px-1023px）で表示を確認
3. モバイル画面（767px以下）で表示を確認

**期待結果**:
- 各画面サイズで適切に表示される
- テーブルが横スクロール可能（モバイル）
- アクションメニューが適切に表示される

### TC-008: エラーハンドリング
**目的**: エラーが発生した場合の適切な処理を確認

**テストケース**:
- ネットワークエラー
- サーバーエラー
- 権限エラー

**手順**:
1. ネットワークエラーをシミュレート
2. エラーメッセージが表示されることを確認
3. エラーから復旧できることを確認

**期待結果**:
- 適切なエラーメッセージが表示される
- エラーから復旧できる
- ユーザーに分かりやすいメッセージが表示される

### TC-009: 権限チェック
**目的**: 管理者権限のないユーザーがアクセスできないことを確認

**手順**:
1. 一般ユーザーでログインする
2. `/admin/users`にアクセスする
3. アクセスが拒否されることを確認する

**期待結果**:
- アクセスが拒否される
- 適切なエラーメッセージが表示される
- リダイレクトされる

### TC-010: ユーザーサブスクリプション管理
**目的**: ユーザーのサブスクリプション情報が正しく表示・管理できることを確認

**手順**:
1. ユーザーのアクションメニューを開く
2. 「サブスクリプション管理」を選択する
3. サブスクリプション情報を確認する
4. サブスクリプションを更新する

**期待結果**:
- サブスクリプション情報が正しく表示される
- サブスクリプションの更新が可能
- 更新結果が反映される

## パフォーマンステスト

### PT-001: 大量データでの表示
**目的**: 大量のユーザーデータでの表示性能を確認

**手順**:
1. 1000件以上のユーザーデータでテスト
2. ページロード時間を測定
3. 検索・ソートの応答時間を測定

**期待結果**:
- ページロード時間が3秒以内
- 検索・ソートの応答時間が1秒以内
- スムーズな操作が可能

### PT-002: 同時アクセス
**目的**: 複数の管理者が同時にアクセスした場合の動作を確認

**手順**:
1. 複数の管理者で同時にアクセス
2. 同じユーザーを同時に更新
3. 競合状態の処理を確認

**期待結果**:
- 同時アクセスが正常に処理される
- 競合状態が適切に処理される
- データの整合性が保たれる

## セキュリティテスト

### ST-001: 認証・認可
**目的**: 適切な認証・認可が実装されていることを確認

**手順**:
1. 未認証でアクセス
2. 一般ユーザーでアクセス
3. 管理者でアクセス

**期待結果**:
- 未認証: ログインページにリダイレクト
- 一般ユーザー: アクセス拒否
- 管理者: 正常にアクセス可能

### ST-002: 入力値検証
**目的**: 不正な入力値が適切に処理されることを確認

**テストデータ**:
- SQLインジェクション攻撃
- XSS攻撃
- 不正なパラメータ

**手順**:
1. 不正な入力値を送信
2. エラーハンドリングを確認
3. セキュリティログを確認

**期待結果**:
- 不正な入力値が拒否される
- 適切なエラーメッセージが表示される
- セキュリティログが記録される

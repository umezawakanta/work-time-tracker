ログイン 要件定義書
====================

最終更新: 2025-08-29

1. 目的
-------
- ユーザーが自身のアカウントで安全にサインインできる機能を提供し、認証済みユーザーのみが保護リソースへアクセスできること。

2. スコープ
-----------
- フロント: ログイン画面（/login）・認証状態の保持・認証失敗時のフィードバック
- バックエンド: `/api/auth/login`, `/api/auth/check`, `/api/auth/refresh`, `/api/auth/logout`
- トークン: AccessToken(短命) + RefreshToken(長命), Local/SessionStorage 管理

3. 役割/前提
-----------
- 一般ユーザー/管理者（isAdmin）
- Vercel プレビュー/本番では実API、ローカルは /api プロキシ

4. 機能要件 (FR)
----------------
1. メール + パスワードでログインできる
2. 成功時に保護ページへ遷移（リダイレクト復帰）
3. 失敗時はエラーメッセージ表示（資格情報不正/ロック/サーバー不調）
4. トークンの自動更新（期限前後）
5. ログアウト時にトークンを完全破棄
6. 管理者は管理者ダッシュボードへアクセス可能

5. 非機能要件 (NFR)
-------------------
- セキュリティ: HTTPS 前提、XSS/CSRF 考慮、脆弱なパスワードをログに出さない
- 可用性: API ダウン時は明確に通知、再試行導線
- アクセシビリティ: フォームはラベル/エラーフィードバック/キーボード操作対応
- パフォーマンス: 初回入力→結果表示まで < 1.5s（ネットワーク除く）

6. 受け入れ基準 (UAT)
----------------------
- 正しい資格情報で 200/OK、アプリに認証状態が反映される
- トークン期限切れ時に自動更新または再ログイン導線
- 誤入力でエラー説明が表示され、スクリーンリーダーでも読める
- ログアウト後に保護ページへ直接遷移するとログインへ誘導

7. UI/UX
--------
- `/login` 1画面。入力: email, password, 送信ボタン。ローディング/エラー表示。
- 成功時は `post_login_redirect` を優先、なければ `/`。

8. 監査/ログ
------------
- ログイン試行（成功/失敗）・トークン更新・ログアウトを計測（dev のみ console、prod はサーバ側）

9. リスクと対応
----------------
- サーバー障害: ローカルにトークンがあれば一時的に維持→後続で再検証
- 401 ループ: 認証系エンドポイント除外ロジックで回避

10. 依存関係
------------
- `src/context/AuthContext.tsx`, `src/services/api/apiConfig.ts`, `src/pages/Login.tsx`

11. 完了条件
------------
- 上記 FR/NFR/UAT を満たすこと
- P0 完了後に「ユーザー登録」「ログアウト」に進む

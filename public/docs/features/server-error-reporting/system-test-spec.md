# サーバエラーレポート機能 総合試験仕様書

## 機能概要
サーバ側のエラー収集・集約・分析機能

## 試験環境
- 本番環境: https://work-time-tracker-five.vercel.app
- テスト環境: http://localhost:3000

## 前提条件
1. 管理者権限を持つユーザーアカウントでログイン済み
2. MongoDB接続が正常に動作している
3. サーバエラーログが収集されている

## 試験項目

### 1. 基本表示機能
- [ ] サーバエラーレポートページにアクセスできる
- [ ] 管理者権限がない場合は403エラーが表示される
- [ ] ページタイトル「サーバエラーレポート」が表示される
- [ ] タブ「エラー一覧」「統計情報」が表示される

### 2. エラー一覧表示
- [ ] 過去のエラーログ一覧が表示される
- [ ] 各エラーログに以下の情報が表示される
  - [ ] 日時
  - [ ] エラーレベル（エラー/警告/情報/デバッグ）
  - [ ] エラーメッセージ
  - [ ] エンドポイント
  - [ ] HTTPステータスコード
  - [ ] ユーザーID
  - [ ] スタックトレース（展開可能）
- [ ] エラーログがない場合は「エラーが見つかりませんでした」が表示される

### 3. フィルター機能
- [ ] 時間範囲フィルターが動作する
  - [ ] 過去1時間
  - [ ] 過去24時間
  - [ ] 過去7日間
  - [ ] 過去30日間
- [ ] エラーレベルフィルターが動作する
  - [ ] すべて
  - [ ] エラー
  - [ ] 警告
  - [ ] 情報
  - [ ] デバッグ
- [ ] エンドポイントフィルターが動作する
- [ ] 検索機能が動作する（メッセージで検索）

### 4. 統計情報表示
- [ ] 総エラー数が表示される
- [ ] エラーレベル別統計が表示される
- [ ] エンドポイント別統計が表示される
- [ ] 時間別統計が表示される
- [ ] トップエラーメッセージが表示される

### 5. エクスポート機能
- [ ] CSVエクスポートボタンが表示される
- [ ] エクスポートが正常に実行される
- [ ] エクスポートファイルに正しいデータが含まれる

### 6. リアルタイム更新
- [ ] 更新ボタンが動作する
- [ ] 新しいエラーがリアルタイムで表示される
- [ ] 統計情報がリアルタイムで更新される

### 7. エラーハンドリング
- [ ] APIエラー時に適切なエラーメッセージが表示される
- [ ] ネットワークエラー時に適切なエラーメッセージが表示される
- [ ] ローディング中はスピナーが表示される

### 8. レスポンシブデザイン
- [ ] モバイルデバイスで適切に表示される
- [ ] タブレットデバイスで適切に表示される
- [ ] デスクトップで適切に表示される

### 9. アクセシビリティ
- [ ] キーボードナビゲーションが可能
- [ ] スクリーンリーダーで適切に読み上げられる
- [ ] 適切なARIAラベルが設定されている

### 10. セキュリティ
- [ ] 管理者権限の検証が正しく動作する
- [ ] 個人情報が適切にマスクされている
- [ ] ログインしていない場合はログインページにリダイレクトされる

## 試験データ
- テスト用のエラーログ: 各種エラーレベルのログ
- テスト用の管理者アカウント: 管理者権限を持つアカウント

## 期待結果
- すべての試験項目が合格する
- 本番環境でMongoDBと正常に連携する
- モックやダミー処理が含まれていない
- エラーが発生しない
- リアルタイムでエラーログが収集・表示される

## 備考
- エラーログはMongoDBのErrorLogコレクションに保存される
- バッチ処理により5秒間隔でログが保存される
- 管理者権限の検証は必須
- 個人情報は適切にマスクされる

# メール通知機能セットアップガイド

## 📧 概要

タスクの追加や期限が近いタスクについて、ユーザーにメールで通知する機能です。

## 🎯 機能一覧

### 1. **通知タイプ**

- **タスク追加通知**: 新しいタスクが追加されたときに通知
- **タスク完了通知**: タスクが完了したときに通知
- **締切接近通知**: タスクの締切が近づいたときに通知
- **デイリーダイジェスト**: 毎日のタスクサマリーを送信
- **週次レポート**: 週間のタスクレポートを送信
- **月次レポート**: 月間のタスクレポートを送信

### 2. **カスタマイズ可能な設定**

- 通知のON/OFF
- 通知先メールアドレス
- 通知タイミング（締切何時間前など）
- 定期レポートの送信時刻・曜日
- 優先度フィルター（指定優先度以上のタスクのみ通知）
- カテゴリーフィルター

## 🚀 セットアップ手順

### 方法1: ユーザーごとの設定（推奨） 🆕

各ユーザーが自分のメールアカウントを使用して通知を受け取ることができます。

1. **通知設定画面にアクセス**
   - サイドメニューから「🔔 メール通知設定」をクリック
   - または http://localhost:3000/settings/notifications にアクセス

2. **メールサービス設定**
   - メールサービスを選択（Gmail、Outlook、Yahoo、カスタムSMTP）
   - 送信元メールアドレスを入力（your-email@gmail.com）
   - アプリパスワードを入力（下記の手順で取得）

3. **通知先設定**
   - 通知を受け取るメールアドレスを入力（通常は送信元と同じ）

### 方法2: システム全体の設定（オプション）

管理者が設定したメールアカウントから全ユーザーに通知を送る場合：

`.env.local` ファイルに以下の環境変数を追加してください：

```bash
# メールサービス設定（Gmail使用例）
EMAIL_SERVICE=gmail
EMAIL_USER=your-email@gmail.com
EMAIL_PASS=your-app-password

# フロントエンドURL（メール内のリンク用）
FRONTEND_URL=http://localhost:3000
```

### Gmailでアプリパスワードを取得する方法

1. [Googleアカウント設定](https://myaccount.google.com/)にアクセス
2. 「セキュリティ」タブを選択
3. 「2段階認証プロセス」を有効化（まだの場合）
4. 「アプリパスワード」をクリック
5. アプリを選択: 「メール」
6. デバイスを選択: 「その他（カスタム名）」を選び「Work Time Tracker」と入力
7. 生成されたパスワードをコピー

### 2. 依存関係のインストール

```bash
# すでにインストール済みの場合はスキップ
pnpm add nodemailer @types/nodemailer node-cron @types/node-cron
```

### 3. サーバーの再起動

```bash
# 開発サーバーを再起動
pnpm dev
```

### 4. 通知設定画面へアクセス

1. ブラウザで http://localhost:3000 を開く
2. サイドメニューから「🔔 メール通知設定」をクリック
3. または直接 http://localhost:3000/settings/notifications にアクセス

## 📱 使い方

### 基本設定

1. **メール通知を有効化**: マスタースイッチをONにする
2. **メールアドレス入力**: 通知を受け取るメールアドレスを入力
3. **設定を保存**: 「設定を保存」ボタンをクリック

### 通知タイミングの設定

#### タスク追加通知

- 新しいタスクが追加されるたびに即座に通知
- 優先度フィルターで重要なタスクのみに絞り込み可能

#### 締切接近通知

- デフォルトは24時間前に通知
- 1〜168時間（1週間）の範囲で調整可能
- 1時間ごとに自動チェック

#### デイリーダイジェスト

- 毎日指定時刻にその日のタスクサマリーを送信
- 完了タスク数、残タスク数、高優先度タスクを含む

### テスト送信

1. 設定を保存後、「テスト送信」ボタンをクリック
2. サンプルのデイリーダイジェストメールが送信される
3. メールが届くことを確認

## 🔧 高度な設定

### カスタムSMTPサーバー

独自のメールサーバーを使用する場合：

1. メールサービスで「カスタムSMTP」を選択
2. 以下の情報を入力：
   - SMTPホスト（例：smtp.your-domain.com）
   - SMTPポート（通常：587または465）
   - SSL/TLSの使用（ポート465の場合はON）
   - 認証情報（ユーザー名とパスワード）

#### 設定例（SendGrid）

```
メールサービス: カスタムSMTP
SMTPホスト: smtp.sendgrid.net
SMTPポート: 587
SSL/TLS: OFF
ユーザー名: apikey
パスワード: your-sendgrid-api-key
```

### 通知フィルター

#### 優先度フィルター

- 1〜5の範囲で最小優先度を設定
- 例：「3以上」に設定すると、優先度1-2のタスクは通知されない

#### カテゴリーフィルター

- 特定のカテゴリーのタスクのみ通知
- 複数カテゴリーの選択可能

### スケジューリング

#### デイリーダイジェスト

- 時刻を「09:00」に設定すると、毎朝9時に送信
- タイムゾーンは「Asia/Tokyo」がデフォルト

#### 週次レポート

- 曜日を選択（0=日曜〜6=土曜）
- 選択した曜日の朝9時に送信

## 🐛 トラブルシューティング

### メールが届かない場合

1. **環境変数の確認**

   ```bash
   # .env.localファイルを確認
   EMAIL_SERVICE=gmail
   EMAIL_USER=正しいメールアドレス
   EMAIL_PASS=正しいアプリパスワード
   ```

2. **メールサービスのステータス確認**
   - 通知設定画面の上部に表示されるステータスメッセージを確認
   - 「Email service is configured and ready」と表示されていることを確認

3. **迷惑メールフォルダの確認**
   - 初回送信時は迷惑メールに分類される可能性あり
   - 送信元を信頼できる送信者として登録

4. **Gmailのセキュリティ設定**
   - 2段階認証が有効になっていることを確認
   - アプリパスワードが正しく生成されていることを確認
   - 「安全性の低いアプリのアクセス」は使用しない（非推奨）

### エラーメッセージ

#### "Email service is not configured"

- 環境変数が正しく設定されていない
- サーバーの再起動が必要

#### "Notifications are disabled"

- メール通知のマスタースイッチがOFFになっている
- 通知設定画面で有効化する

#### "Failed to send notification"

- ネットワーク接続の問題
- メールサービスの一時的な問題
- 認証情報の誤り

## 🔒 セキュリティ

### 推奨事項

1. **アプリパスワードの使用**
   - 通常のGmailパスワードではなく、アプリ専用パスワードを使用

2. **ユーザーごとの設定**
   - 各ユーザーが自分のメールアカウントを使用することで、セキュリティを向上
   - パスワードは暗号化して保存（実装予定）

3. **環境変数の管理**
   - `.env.local`はGitにコミットしない
   - 本番環境では環境変数を安全に管理

4. **レート制限**
   - 大量のメール送信を防ぐため、レート制限を実装済み

5. **ユーザー認証**
   - 実際の本番環境では、適切なユーザー認証を実装

6. **パスワード保護**
   - ユーザーのメールパスワードは本番環境では暗号化して保存する必要があります
   - 現在はデモ用のため平文で保存されています（注意）

# 自動フォールバック機能ガイド

## 概要

レート制限に達した際に、自動的に別のAIプロバイダーに切り替える機能です。これにより、分析の中断を防ぎ、継続的なサービス提供が可能になります。

## 機能の仕組み

### 自動切り替えフロー

1. **レート制限検出**: プロバイダーから429エラーを受信
2. **失敗カウント**: 同じプロバイダーで3回連続失敗を記録
3. **代替プロバイダー選択**: 利用可能な次のプロバイダーを自動選択
4. **切り替え実行**: 新しいプロバイダーで処理を継続
5. **ユーザー通知**: 切り替えをUIで通知

### プロバイダー優先順位

```
1. Gemini（無料枠が大きい）
2. Claude（バランスが良い）
3. Ollama（ローカル実行）
4. OpenAI（最終手段）
```

## 使用方法

### 1. 自動フォールバックの有効化

4象限タブの右上にある「自動切替」スイッチをONにします。

- ⚡ **黄色**: 有効（デフォルト）
- ⚡ **グレー**: 無効

### 2. フォールバック状態の確認

プロバイダーがフォールバック中の場合、「フォールバック中」バッジが表示されます。

### 3. 手動での復旧

元のプロバイダーが回復した場合、5分後に自動的に元に戻ります。

## 動作条件

### フォールバックが発生する条件

- 同一プロバイダーで**3回連続**でレート制限エラー（429）
- 自動フォールバックが**有効**になっている
- 代替プロバイダーが**利用可能**

### フォールバックしない条件

- 自動フォールバックが**無効**
- 利用可能な代替プロバイダーが**ない**
- 全てのプロバイダーが**レート制限中**

## 復旧メカニズム

### 自動復旧

- **待機時間**: 最後の失敗から5分経過後
- **可用性チェック**: プロバイダーのAPIキー/接続状態を確認
- **自動切り戻し**: 条件を満たせば元のプロバイダーに自動復帰

### 手動復旧

プロバイダー選択ドロップダウンから手動で元のプロバイダーを選択可能

## 設定例

### シナリオ1: コスト重視

```
メインプロバイダー: Gemini
フォールバック順: Ollama → Claude
自動切替: ON
```

**メリット**: 無料枠を最大限活用、ローカル実行で追加コストなし

### シナリオ2: 信頼性重視

```
メインプロバイダー: Claude
フォールバック順: Gemini → OpenAI
自動切替: ON
```

**メリット**: 高い可用性、常に分析が継続

### シナリオ3: プライバシー重視

```
メインプロバイダー: Ollama
フォールバック順: なし
自動切替: OFF
```

**メリット**: データが外部に送信されない

## トラブルシューティング

### Q: フォールバックが頻繁に発生する

**原因**: タスク数が多すぎる、または短時間に多くの分析を実行

**対策**:

1. 優先度フィルターでタスク数を削減
2. 分析の実行間隔を空ける
3. より大きな無料枠のプロバイダーを使用

### Q: 元のプロバイダーに戻らない

**原因**: 5分の待機時間が経過していない、またはAPIキーの問題

**対策**:

1. 5分以上待つ
2. APIキーの有効性を確認
3. 手動でプロバイダーを切り替える

### Q: フォールバックが機能しない

**原因**: 自動切替が無効、または全プロバイダーが利用不可

**対策**:

1. 自動切替スイッチをONにする
2. 少なくとも2つ以上のプロバイダーを設定
3. APIキーが正しく設定されているか確認

## パフォーマンスへの影響

### メリット

- ✅ **継続性**: レート制限による中断を防ぐ
- ✅ **自動化**: 手動介入不要
- ✅ **柔軟性**: 複数プロバイダーの活用
- ✅ **回復力**: 自動的に元の状態に復帰

### デメリット

- ⚠️ **一貫性**: プロバイダーによる分析結果の差異
- ⚠️ **コスト**: 有料プロバイダーへの意図しない切り替え
- ⚠️ **複雑性**: 状態管理が複雑になる

## ベストプラクティス

### 1. プロバイダー設定

- **最低2つ**のプロバイダーを設定
- **無料枠**があるプロバイダーを優先
- **Ollama**をフォールバック先に含める

### 2. モニタリング

- フォールバック発生時の**通知を確認**
- **失敗パターン**を把握して対策
- 定期的な**プロバイダー状態**の確認

### 3. コスト管理

- **OpenAI**は最終手段として設定
- **優先度フィルター**と併用
- **キャッシュ機能**を活用

## API制限の目安

| プロバイダー | レート制限 | 推奨間隔 | 最大タスク数/分析 |
| ------------ | ---------- | -------- | ----------------- |
| Gemini       | 60/分      | 1秒      | 20                |
| Claude       | 50/分      | 1.2秒    | 20                |
| OpenAI       | 3-10/分    | 6-20秒   | 5                 |
| Ollama       | なし       | なし     | 50                |

## まとめ

自動フォールバック機能により：

- 🔄 **シームレスな切り替え**: レート制限を自動回避
- 📊 **高可用性**: 分析サービスの継続性確保
- 💰 **コスト最適化**: 無料枠を優先的に使用
- 🔧 **自動復旧**: 元のプロバイダーへの自動復帰

レート制限を気にせず、安定した4象限分析が可能になります。

# Gemini API レート制限対策ガイド

## 現在の状況

Gemini APIの429エラー（Too Many Requests）に対応するため、以下の対策を実装しました。

## 実装された対策

### 1. レート制限の設定

```javascript
{
  requestsPerMinute: 10,        // 1分間に10リクエストまで
  retryDelay: 2000,             // リトライまで2秒待機
  maxRetries: 3,                // 最大3回までリトライ
  batchSize: 2,                 // 同時処理は2タスクまで
  maxTasksPerAnalysis: 20       // 一度に分析するタスク数は20まで
}
```

### 2. キャッシュ機能

- 一度分類したタスクはキャッシュに保存
- 同じタスクの再分類を防ぐ
- 最大100件までキャッシュ

### 3. リトライロジック

- 429エラーの場合、指数バックオフでリトライ
- 2秒、4秒、8秒と待機時間を増やす

### 4. フォールバック分類

- API制限に達した場合、ヒューリスティック分析を使用
- 十分な精度で4象限に分類可能

### 5. バッチ処理

- タスクを2件ずつ順次処理
- 各バッチ間で2秒の待機時間

## エラーが発生した場合

### 症状

```
POST https://generativelanguage.googleapis.com/...?key=... 429 (Too Many Requests)
```

### 対処法

#### 1. しばらく待つ

- 自動的にリトライとフォールバックが実行されます
- 数秒〜数分待てば制限が解除されます

#### 2. タスク数を減らす

- 一度に分析するタスクを20件以下に制限
- 不要なタスクを削除またはアーカイブ

#### 3. 自動更新を無効化

- 4象限マトリックスの自動更新をOFFに
- 必要な時だけ手動で更新

#### 4. キャッシュを活用

- 同じタスクは再分類されません
- ページをリロードしてもキャッシュが効きます

## APIキーのアップグレード

### 無料プランの制限

- 1分間に15リクエストまで
- 1日1,500リクエットまで

### 有料プランへのアップグレード

1. [Google AI Studio](https://makersuite.google.com/app/apikey)にアクセス
2. 「Billing」セクションで有料プランを選択
3. より高いレート制限を取得

## フォールバック分類について

APIが利用できない場合でも、以下の基準で自動分類されます：

### 分類基準

- **緊急度**: 期限までの日数で判定
  - 3日以内: 高
  - 7日以内: 中
  - それ以上: 低

- **重要度**: 優先度とカテゴリで判定
  - 優先度4-5: 高
  - 優先度2-3: 中
  - 優先度1: 低

### 精度

- 基本的な分類は十分な精度
- AI分析ほど詳細ではないが実用的
- 推奨アクションは汎用的

## トラブルシューティング

### Q: エラーが続く場合

A: ブラウザのキャッシュをクリアして再度アクセス

### Q: 分析が遅い場合

A: タスク数を減らすか、自動更新を無効化

### Q: キャッシュをクリアしたい場合

A: ブラウザの開発者ツールでコンソールに以下を入力：

```javascript
QuadrantClassificationService.getInstance().clearCache();
```

## 推奨設定

### 開発環境

- autoRefresh: false
- refreshInterval: 10分以上
- タスク数: 20件以下

### 本番環境

- 有料APIキーの使用を推奨
- autoRefresh: true (有料プランのみ)
- refreshInterval: 30分以上
